# Feature Simplification Audit

## Purpose

当前项目已经从旧主线设想回到更小、更稳的产品面：A 股短线结构工作台。

```text
候选池 -> 候选详情 -> 单股确认 -> 数据后台
```

裁剪判断只看一个问题：

> 这个功能是否帮助用户从本地候选中找到值得确认或需要规避的股票，并回到图表完成执行判断？

如果答案是否，它应该移到数据后台、标记为实验项，或从当前产品面退役。

## Keep As Core

| Area | Keep | Reason |
| --- | --- | --- |
| 候选池 | 参与候选、风险验证、轻量筛选、结构概览 | 每日第一步是快速定位待确认和待规避股票。 |
| 候选详情 | 决策结论、交易计划、依据、风险、只读画像证据 | 帮用户判断下一步是否打开单股确认。 |
| 单股确认 | K 线、综合信号、交易计划、止损、仓位、失效条件 | 最终执行必须落在单股图表。 |
| 数据后台 | 扫描任务、数据源健康、概念刷新、板块行情、缓存清理、历史快照 | 操作治理不应干扰候选判断。 |

## Move Or Hide

| Feature | Problem | Decision |
| --- | --- | --- |
| 修复观察一级 tab | 让候选池看起来有三套并列主流程，但它更像底层辅助信号 | 从一级入口移除，保留 `bottom_div` 后端兼容。 |
| 候选详情人工校准表单 | 决策流中出现编辑数据动作，容易打断确认节奏 | 移出默认候选详情，仅保留只读证据展示。 |
| 同步批扫 `/api/scan_batch` | 长请求、并发资源难控，且与后台任务体系重复 | 返回退役状态，统一使用 `/api/scan_jobs`。 |
| 概念图谱 | 证据强度不足，容易被误解为核心决策来源 | 标为实验项，不计入核心数据源可用率。 |
| 旧主线文档和术语 | 与当前代码和测试契约不一致 | 归档到 `docs/archive/`，当前文档只描述现行系统。 |

## Keep As Supporting Capability

| Capability | Keep Why | Placement |
| --- | --- | --- |
| `bottom_div` 扫描类型 | 历史快照、策略测试、底层修复信号仍依赖它 | 内部兼容层 |
| 画像证据写入 API | 后台治理或未来研究工具仍可能使用 | 数据后台 / 脚本 |
| 概念图谱 API | 实验研究和关系边维护仍可复用 | 实验层 |
| 扫描历史与回放 | 用于验证策略稳定性 | 数据后台 |
| 缓存清理与数据源状态 | 用于恢复和治理 | 数据后台 |

## Boundary Rule

不要因为功能在 UI 上显得嘈杂就直接删除底层能力。先判断它是否还被快照、测试、脚本或 API 依赖；如果仍有依赖，就从主产品面移出并标清位置。
