# C 信号 V2 策略需求规格

> 更新日期：2026-09-14  
> 状态：V2 已成为唯一主链；P1-P12、P18、P19、P22、P23、P24 已完成最小闭环；P25-A/P25-B/P25-C/P25-D 已完成第一阶段。  
> 依据：当前项目代码、`docs/c-signal-v2-design.md`、`docs/c-signal-v2-market-refresh-report.md`、以及 `/Users/vainve/obsidian/奇衡-dk/以短线交易秘诀为生/` 原文笔记的整体方法论  
> 边界：本文定义下一阶段需求。旧 C 只作为备用策略素材记录在 `docs/legacy-c-signal-reference.md`，不得恢复为主链。

## 1. 当前问题

当前系统已经能运行，且 V2 已经成为扫描、单股分析、图面标记和交易许可的唯一主链。旧 C/V2 临时切换、旧 composite 图面事件默认展示和旧 C 入池口径已经下线。

当前真实链路是：

```text
行情数据
→ V2 facts
→ V2 state
→ 环境许可
→ Plan Gate / Exit Gate
→ 工作台入池与图面展示
```

现在最主要的问题不是“V2 是否独立”，而是“V2 的观察类语义仍太粗”：

```text
C候 过宽
→ 普通结构、回踩蓄势、破位修复、强修复待触发混在一起
→ 用户容易把观察点误解为买点
→ 无持仓时又容易把风险事实误解成卖出/减仓动作
```

因此下一阶段的核心目标是：继续保留 V2 单主链，但把 `C候` 拆成更清楚的候选子状态，并让图面按“无持仓/有持仓”两个处境展示不同动作语言。

## 2. 设计原则

### 2.1 技术指标只做 trigger

MACD、KDJ、Williams %R、布林、分型、攻击日、起爆点都不能单独预测涨跌。它们只能回答一个局部问题。

要求：

- 指标不得直接生成买入结论；
- 触发器必须依赖前置状态；
- 前置状态未通过时，触发器只能显示为观察事实；
- 任何高分都不能越过交易许可。

### 2.2 成交量只决定是否值得关注

成交量不再作为单股买入强加分项。它主要回答：

```text
这个市场/板块/个股是否值得看？
是否出现资金活动迹象？
是否从缩量压缩进入活跃阶段？
```

它不直接回答：

```text
现在能不能买？
是不是主力建仓？
是不是确定上涨？
```

### 2.3 收益风险比必须前置

如果一笔交易无法定义止损、目标空间或至少 2R 的收益风险比，就不能进入可执行池。

要求：

- `C研` 不要求止损价；
- `C候` 要求结构失效条件，但不强制交易止损；
- `C回 / C突 / C爆` 必须有入场价、止损价、至少 2R、仓位预算；
- `C风` 只处理风险，不生成新的入场计划。

### 2.4 评分只解释成熟度，不替代许可

当前 `setup_score / confirm_score / risk_score` 容易被理解成分高就能买。V2 评分应改为解释“条件成熟到哪一步”。

建议分数：

| 分数 | 含义 | 是否能决定交易 |
| --- | --- | --- |
| `attention_score` | 是否值得关注 | 否 |
| `rr_score` | 收益风险比是否合格 | 可拦截 |
| `market_permission_score` | 市场/板块是否允许 | 可拦截 |
| `structure_score` | 结构是否清楚 | 否 |
| `trigger_quality` | 触发是否明确 | 否 |
| `execution_risk` | 执行风险是否过高 | 可拦截 |
| `plan_quality` | 计划是否可执行 | 可拦截 |

其中真正能决定是否可执行的不是总分，而是许可枚举：

```text
forbidden
watch_only
structure_only
pullback_allowed
breakout_allowed
attack_allowed
risk_only
```

## 3. 信号角色需求

### 3.1 `C研` 研究观察

定位：只说明值得研究，不说明可以买。

进入条件：

- 威廉时钟进入压缩、倒计时或收缩后扩张；
- 成交量出现值得关注的变化；
- 底背离、阴包阳创新低等极端观察事实；
- 市场或板块进入可研究状态。

禁止：

- 不进入可执行池；
- 不展示仓位；
- 不强制止损价；
- 不与 `C爆` 同权排序。

验收：

- 用户能一眼看出 `C研` 是观察，不是买点；
- `C研` 不会触发交易计划 ready；
- `C研` 可以提供观察失效条件。

### 3.2 `C候` 结构候选

定位：说明价格结构可跟踪，但还没有扣扳机。

进入条件：

- 底分型或双底低点抬高；
- 矩形边界和 C 点可估算；
- 关键支撑/压力位可定义；
- 弱转强结构正在形成但尚未触发。

要求：

- 必须输出结构来源；
- 必须输出关键上沿、下沿或失效条件；
- 必须输出候选子状态；
- 默认进入结构观察池，不进入可执行池。

P25 子状态：

| 子状态 | 图面短标 | 说明 | 是否买点 |
| --- | --- | --- | --- |
| `structure_candidate` | `候` | 普通分型、矩形或结构位置可观察 | 否 |
| `pullback_setup` | `候` | 回踩蓄势，价格回到可观察区域但尚未触发 | 否 |
| `weak_repair_candidate` | `候?` | 破位区出现底分型或低点收敛，旧结构已破，新结构未确认 | 否 |
| `strong_repair_watch` | `待触` | 回踩或破位后出现强修复证据，次日可能反包 | 否 |
| `reversal_confirmed` | `触` | 放量反包、站回防守线/中轴/量峰压力 | 不是最终买点，仍需 Plan Gate |

验收：

- `C候` 能回答“在哪里观察”和“什么情况下作废”；
- 没有 trigger 时不显示为可交易；
- `候?` 和 `待触` 不显示成买点；
- `待触` 必须给出次日或盘中确认价；
- 风险状态出现时，`C候` 被 `C风` 覆盖。

### 3.3 `C修` 修复观察

定位：承接旧 `C观`，但从参与候选降级为修复观察。

进入条件：

- 下跌后出现底背离、动量修复或多空力度改善；
- 旧 composite confirm 命中，但尚未满足 V2 可执行许可；
- 结构还不完整，或者收益风险比尚未确认。

要求：

- 不再作为默认参与候选主入口；
- 必须写清楚还缺什么确认；
- 只有后续出现结构和 trigger，才能升级。

验收：

- `C观` 在 V2 中不再被用户理解为买点；
- 修复观察与可交易信号在 UI 上明确分层；
- 旧策略对照仍能保留，不影响回滚。

### 3.4 `C回` 回踩参与

定位：结构许可后的回踩交易计划。

进入条件：

- 市场/板块许可未禁止；
- 个股结构仍有效；
- 回踩靠近可定义支撑、矩形下沿、均线参考或 C 点附近；
- trigger 出现；
- 交易计划通过。

计划要求：

- 入场价；
- 止损价；
- 止损距离；
- 至少 2R，优先 3R；
- 单笔风险预算；
- A 股手数取整后的建议股数。

验收：

- 无止损不 ready；
- 低于 2R 不 ready；
- 风险分或结构失效时转 `C风`；
- 不因为单纯缩量回踩自动入场。

### 3.5 `C突` 突破触发

定位：右侧突破 trigger，负责扣扳机，不负责预测后续空间。

进入条件：

- 明确突破价：昨日高点、近 N 日前高、矩形上沿或结构压力；
- 前置趋势/板块许可通过；
- 止损位能定义；
- 高开、过热、MA20 偏离、量比异常经过计划层审查。

禁止：

- 不使用“有效突破后确认”这类未来函数；
- 不把放量突破直接等同于可买；
- 不在高位过热状态下继续加权。

验收：

- 次日高开超过阈值时计划提示禁追或等待；
- 距 MA20 过远时降级或 blocked；
- `C突` 样本需单独回测分桶。

### 3.6 `C爆` 起爆/攻击日

定位：最容易被误解的信号。它不是“强买”，而是“强 trigger 候选”。

进入条件：

- 攻击日结构成立；
- 或起爆点触发；
- 或三重滤网第三层触发；
- 同时满足前置结构、收益风险比、市场/板块许可。

当前需修正：

- 图面上的 `C爆` 目前只是攻击日/起爆事实；
- 不能因为图面出现 `C爆` 就进入可执行池；
- 未来应拆分为 `C爆事实` 和 `C爆可执行` 两个状态。

验收：

- `C爆` 数量明显少于当前图面事实点；
- 未通过交易计划的 `C爆` 显示为观察或 blocked；
- 可执行 `C爆` 必须带止损、2R/3R、仓位。

### 3.7 `C风` 风险处理

定位：风险优先级最高，覆盖机会解释。

进入条件：

- 跌破计划止损；
- 跌破结构 C 点；
- 顶分型、顶背离、过热回落；
- 趋势破坏；
- 持仓峰值回撤触发保护利润。

要求：

- 输出处理动作：退出、减仓、暂停、保护利润；
- 不参与机会加分；
- 不被新的 `C研 / C候` 覆盖；
- 空仓视角不直接显示为 `卖` 或 `减`；
- 持仓视角才允许输出 `减 / 撤 / 卖`。

验收：

- 同日同时出现机会和风险时，风险优先；
- 风险池排序优先展示强制处理项；
- 前端不把 `C风` 显示为普通提示；
- 未确认持仓生命周期时，跌破结构显示 `破`，不是 `卖`。

## 4. 板块共振需求

当前板块共振主要来自候选池内部统计：

```text
板块内机会数
+ 修复观察数
+ 平均 rank
+ 最高 rank
- 风险数量
```

这能说明“候选是否集中”，但还不能说明作者意义上的环境许可。

V2 需要拆成四层：

| 层级 | 问题 | 结果 |
| --- | --- | --- |
| 市场状态 | 大盘/主要指数是否允许短线做多 | 禁止、观察、允许 |
| 板块状态 | 板块是否强于市场并有宽度 | 禁止、观察、允许 |
| 题材关系 | 个股与板块/概念关系是否真实 | 核心、事件、弱关联、过期 |
| 个股相对强弱 | 个股是否强于所属板块 | 加权、普通、降级 |

验收：

- 板块共振不直接生成买点；
- 板块弱时可阻止 `C突 / C爆` 升级；
- 板块强只提供许可，不代替个股结构；
- 个股弱于板块时降低优先级。

## 5. 候选池需求

V2 候选池应从一个列表拆成分层队列。

建议队列：

```text
研究观察池：C研
结构候选池：C候 / C修
可执行计划池：通过许可的 C回 / C突 / C爆
风险处理池：C风
```

当前约束：

- 现有 `opportunity / bottom_div / risk` 池继续作为前端一级入口保留；
- V2 在前端和接口中输出新的 `v2_queue`；
- 扫描入池必须来自 V2 当前状态；
- 旧 C 字段只作为备用解释，不参与主链排序；
- `opportunity` 池默认不得暗示全部样本可买，应区分 `structure_watch / trigger_watch / plan_ready`。

验收：

- 用户能看到一只股票为什么在哪个池；
- V2 池不再完全依赖 `composite_*` 事件；
- `C爆` 未通过计划时不进入可执行计划池。

## 6. 图面展示需求

当前 V2 图面点虽然已经不再默认展示旧 C，但仍存在“同一个技术事实在不同用户处境下含义不同”的问题。后续图面必须分为无持仓视角和有持仓视角。

### 6.1 无持仓视角

展示：

- `看`：值得研究；
- `候`：结构候选；
- `候?`：破位后的弱修复观察；
- `待触`：强修复待触发；
- `触`：触发事实，仍需计划；
- `阻 / 警 / 破`：阻力、风险或结构破坏事实。

用途：帮助空仓用户判断“是否值得看、是否危险、是否不宜追”，不输出卖出或减仓动作。

### 6.2 有持仓视角

展示：

- `持`：原计划仍有效；
- `减`：撞击强阻或过热，建议降低暴露；
- `撤`：主动防御，早于最终卖出；
- `卖`：持仓生命周期中的防守线失效或终极退出。

用途：帮助已有仓位的用户管理交易，不把普通风险事实直接当成最后卖点。

验收：

- 默认视图不满屏；
- 研究点弱化；
- 空仓视角不显示 `卖 / 减`；
- 有持仓视角下 `撤` 应早于 `卖`；
- 可执行 `买` 必须能展开交易计划。

## 7. 下一阶段实现顺序

### P25-A：候选子状态建模

状态：已完成第一阶段。

目标：把 `C候` 拆成普通结构候选、回踩蓄势、破位修复、强修复待触发、反包确认。

产物：

- `candidate_substate`；
- `display_label`；
- `confirmation_price`；
- `invalidation_price`；
- `missing_confirmations`。

验收：

- 普通 `C候` 不再和强修复样本混在一起；
- `候?`、`待触`、`触` 能在解释面板中说清楚差别；
- 任何子状态都不能绕过 Plan Gate 直接变成买点。

已落地：

- 后端 `v2_state_model` 输出 `candidate_substate / candidate_display_label / candidate_confirmation_price / candidate_invalidation_price`；
- 扫描结果顶层与 compact 工作台响应保留候选子状态字段；
- 旧快照读取时可根据已有 `v2_state_model` 和 facts 做兼容回填；
- 工作台候选卡主标签会优先显示 `候? / 待触 / 触` 等通俗短标。

### P25-B：强反包样本复盘

状态：已完成第一阶段。

目标：复核 2026-09-11 至 2026-09-14 的强反包样本，找到“待触”前置条件，而不是把所有 `C候` 放宽。

重点样本：

```text
300903 科翔股份
301021 英诺激光
301132 满坤科技
688383 新益昌
300112 万讯自控
```

验收：

- 能区分强修复前置结构和普通候选噪音；
- 不把 9 月 11 日普通 `C候` 回测表现误读为策略有效；
- 输出可计算的次日确认规则。

已落地：

- 提炼第一版 `strong_repair_watch` 补充条件：短线箱体不可用、`repair_impulse = true`、价格位于 MA250 上方、上方 15% 内存在强目标阻力且 `strength_score >= 90`；
- 该规则在 2026-09-11 opportunity 样本中命中 23 只，至 2026-09-14 平均收盘收益 `+3.883%`、胜率 `65.22%`、10% 以上样本 4 只；
- `301132 / 300112` 已归入 `待触`，`300903` 归入 `触` 但仍被 Plan Gate 拦截，`301021 / 688383` 暂不因事后上涨而强行升级；
- `待触` 仍不是买点，只能提示次日重点观察确认价。

### P25-C：图面双视角改造

目标：单股页支持无持仓/有持仓显示切换，默认无持仓。

状态：已完成第一阶段。

改造点：

- 后端输出 `display_context` 或等价字段；
- 空仓视角把 `sell` 降级为 `break/risk`；
- 空仓视角把 `scale_out` 降级为 `resistance/watch`；
- tooltip 保留原始事实和 C 信号来源；
- 主图显示通俗短标。

实现说明：

- 单股图表新增 `空仓 / 持仓` 分段切换；
- 策略事实层继续使用 `markerRole = observe / buy / scale_out / sell`；
- 展示层按视角二次翻译：空仓 `sell -> 破/候?`，空仓 `scale_out -> 阻`，持仓 `sell/scale_out/top/buy -> 卖/减/撤/持`；
- 同日存在破位与底部候选时，空仓优先显示 `候?`，避免把“破位区底分型”误读成简单卖点；
- tooltip 显示原始事实来源，保留审计线索。

验收：

- 空仓图面不出现 `卖 / 减`；
- 持仓图面能看到 `持 / 减 / 撤 / 卖`；
- 601330 的 8 月 24 日这类“破位 + 底分型”优先显示为 `候?`，而不是简单卖出。

### P25-D：次日确认/盘中触发解释

目标：对 `待触` 给出用户能执行的右侧确认条件。

状态：已完成第一阶段。

改造点：

- 输出待确认价，例如前一日高点、防守线、箱体中轴、量峰压力；
- 输出确认失败条件；
- 在单股页解释“为什么今天不是买点，但明天需要看什么”。

实现说明：

- 后端状态模型新增 `candidate_trigger_plan`；
- 输出 `confirmation_price / confirmation_label / invalidation_price`；
- 输出 `distance_to_confirmation_pct / distance_to_invalidation_pct`；
- 输出 `intraday_rule / next_session_rule / failure_rule`；
- 工作台卡片展示 `触发 / 失效` 证据 chip；
- 单股页 V2 诊断展示 `待触计划 / 盘中/次日 / 失效处理`；
- 历史快照在缺少该字段时会用已有 candidate 字段回填。

验收：

- `待触` 不提前显示为买；
