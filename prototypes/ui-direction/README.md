# UI Direction Prototypes

这两份静态原型只验证主入口和信息层级，不代表最终视觉稿，也不接生产 API。
两者使用相同组件、相同样例数据和相同图表，避免把视觉偏好误判成工作流优势。

- `candidate-first.html`：先发现和横向比较候选，再进入单票确认。
- `single-stock-first.html`：已有代码时直接查看行情和信号，候选队列作为上下文。

直接在浏览器打开任一 HTML 即可。样例内置代码：`300829`、`600063`、
`002410`、`000858`。

验证时分别完成以下任务并记录时间、回退次数和主观把握：

1. 没有预设标的时，找到一只值得继续核对的参与候选，并说明缺少的确认。
2. 已知代码 `300829` 时，查看最新 K 线状态、正式信号和失效条件。
3. 从一只风险票切换到参与候选，比较两者的许可与下一步动作。

候选优先若明显改善任务 1 且不显著拖慢任务 2，可作为默认首页；单票优先若任务
2 是日常绝大多数场景且候选上下文仍容易到达，则可作为默认首页。也可以保留两种
平级入口，但不应把两套完整工作台同时塞进首屏。
